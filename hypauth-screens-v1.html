HypAuth

Thirteen screens for an offline TOTP authenticator. iOS and Android, single Flutter codebase, no backend. Codes are generated on device and secrets never leave the Keychain or Keystore.

Two weights only, 400 and 500. Nothing is bold beyond 500. Codes and any machine value use the mono face so digits align across rows. Everything else is sentence case.

Standing rules

No filled containers. Grouping is done with a 1px hairline or with whitespace. There is no Card anywhere in this app. The single exception is the active drag row, which uses Wash.

No border radius on containers. Radius appears only on buttons (24px pill), sheets (18px), and the device frame itself. Rows and dividers stay square.

The code is the largest thing on screen. If any element competes with it for weight, that element is wrong.

One accent, five uses. Countdown fill, search match underline, active drag handle, toggles, scan line. Adding a sixth use dilutes it.

Danger is a state. Red appears in the final 10 seconds of a code, on failed unlock, and on removal. It is never decorative.

Secrets are never rendered. No screen displays, reveals, or exports a TOTP secret in V1. There is no UI code path that reads one.

Bottom weighting. Primary actions sit in the lower third, within thumb reach. Titles may sit high; buttons never do.

Copy names its consequence. Destructive confirmations state what is lost, not just what is deleted.
